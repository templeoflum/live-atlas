## Cues

One at a time. Next moves to the next cue, and after the last one it starts again.

| # | Cue | Shortcut-table row (Mac / Windows) | Counts as seen when |
|---|---|---|---|
| 1 | Switch to the other main view (Session or Arrangement). | Toggle Session/Arrangement View · Tab / Tab | `focused_document_view` changes |
| 2 | Hide the Browser. If it is hidden then show it. | Hide/Show Browser · Cmd Option B or Cmd Option 5 / Ctrl Alt B or Ctrl Alt 5 | `is_view_visible Browser` changes |
| 3 | Select the track next to this one. | Select Neighboring Clip/Slot · arrow keys / arrow keys (left or right, in Session View with a clip slot selected) | `selected_track` changes |

The keys stay hidden until Show keys is on. Any way of making the change counts, so clicking also gives "seen". The device can't tell which key was pressed.

## What it reads from Live

| LOM path | Member | How |
|---|---|---|
| `live_app view` (Application.View) | `focused_document_view` | Observed. Live reports `Session` or `Arranger`. |
| `live_app view` | `is_view_visible Browser` | Asked every 200 ms. It is a function, so it can't be observed. |
| `live_set view` (Song.View) | `selected_track` | Observed. |
| the selected track | `name` | Read for the display. |

The bottom line of the device shows Live's state as it reads it (View, Track, Browser). It's filled in when the device loads, before any cue, and keeps updating. Member names are from the Cycling '74 LOM pages for [Application.View](https://docs.cycling74.com/apiref/lom/application_view/) and [Song.View](https://docs.cycling74.com/apiref/lom/song_view/).

## Loading it (Live 12 Suite)

1. Open a new or scratch Set.
2. In Finder, open `live-atlas/practice/` and drag `watcher-probe.amxd` onto any track in Live. On a MIDI track with no instrument it still loads, as an audio effect.
3. The device appears in Device View at the bottom. If Clip View is showing instead, press Shift Tab.

Don't press the device's Edit button or save it from Max: that writes a copy somewhere. If you save the Set, the Set refers to the file where it is. Leave out Collect All and Save, which would copy the device into the project.

## What you should see

- On load: "Press Next for the first cue." The state line shows something like `View: Session  Track: 1-MIDI  Browser: shown`.
- Next shows cue 1 and the word `watching`. Press Tab: the state line changes to `View: Arranger` and the word changes to `seen`.
- Show keys shows the row name and keys under the cue. Press it again to hide them.
- Next goes to cue 2 (Browser), then cue 3 (track). Each starts at `watching`.
- Stop clears the cue and closes the watching. The state line keeps updating.

## What it is for

The question is whether a cue stays readable while focus is in Live. Things to watch for (all **unchecked**):

- Does the device stay in view? Shift Tab to Clip View, or a click on another track, swaps Device View to something else. The cue then disappears with it.
- Cue 3 changes the selected track, so Device View then shows *that* track's devices and the probe is out of view. It's still watching (`seen` is set), but you can't see it until you click back. That may be the probe's main answer for track cues.
- Once you've clicked a button on the device, does Tab still switch views, or does the device catch the key?
- Does `seen` arrive quickly enough to feel tied to the move? The Browser cue can lag up to 200 ms.

## Checked here, not in Live

- The script reads the three rows from the atlas and stops if one is missing.
- It writes Live's own `.amxd` container: the same `ampf`/`aaaa`/`meta`/`ptch` header as Live's bundled *Max Audio Effect.amxd*. It then re-reads the file, parses the JSON, and checks every patch cord against the boxes' inlet and outlet counts.
- The object counts were compared with Max 9.1.5's reference pages in the Live bundle.
- Nothing runs Max here. Whether Live opens it and how it looks are for Hedawn's load in Live 12 Suite.
